Frequently Asked Questions

Direct, source-grounded answers to technical questions about architecture, toolchains, execution boundaries, and safety.

Does agentic-go replace gopls?

No. agentic-go bundles an exact, tested gopls v0.21.0 companion named agentic-go-gopls. It uses gopls as a private stdio sidecar for type analysis, definition lookups, and symbol references, while layering immutable snapshot lineage, change continuity contracts, guarded deterministic refactoring, and executed whole-package verification around it.

Can agentic-go modify my files or Git history?

agentic-go will never mutate Git repository state (it never executes git add, git commit, git branch, or git stash).

The only mutating tool is go_refactor, which operates under strict preview-and-apply guarantees: it modifies only existing contained non-generated files after checking that all target file preimages match their baseline hash, and writes a recovery journal before touching the disk.

What execution privileges does verification require?

Execution tools (such as go_verify_change and go_test_structured) compile and run Go test suites using the local go toolchain. They execute with the same OS user permissions and environment privileges as running go test ./... manually in your terminal.

All workspace paths are contained and symlink-resolved, but this is containment, not a sandbox. Do not run verification on untrusted or hostile code.

Which Go versions and operating systems are supported?

We explicitly support Go 1.25, Go 1.26, and Go 1.27 on macOS (Darwin) and Linux for both amd64 and arm64 architectures.

Server startup verifies the host toolchain against the workspace's minimum Go requirement using GOTOOLCHAIN=local.

Does agentic-go embed an LLM or make external API calls?

No. agentic-go is 100% deterministic local software. It does not embed any large language models, does not require an API key, and makes zero network calls. The bundled gopls sidecar has telemetry permanently disabled.

How does agentic-go achieve a 0% false-positive baseline?

In calibration across 10 pinned Go repositories and 467 reviewed findings, our static analyzers produced zero false positives. Our analyzers are deliberately conservative: when source patterns cannot be definitively proven problematic, the engine reports an explicit uncertainty lens rather than guessing or spamming low-confidence warnings.

What is the difference between personal and organization module paths?

The module identity for v1 is github.com/agentic-mcps/go. The previous personal module path (github.com/ashwingopalsamy/agentic-go) was migrated; they remain distinct module identities without automatic aliasing. See Module Migration for details.
