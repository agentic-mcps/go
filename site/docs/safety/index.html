Safety & Trust Boundaries

agentic-go is engineered with transparent security controls. We define our protections as containment rather than sandboxing.

Containment vs. Sandboxing

  • Containment Controls: All filesystem lookups, AST analysis, and subprocess operations are resolved against the symlink-canonicalized workspace root. Subprocesses share cancellation contexts, bounded output buffers, and execution timeouts.
  • Execution Privileges: When verification compiles and runs Go tests (go test ./...), that code runs with the exact OS permissions of the user running the process. Do not execute verification against untrusted repositories.

Tool Execution Classes

Tool Class Tools Execution Privileges & Guarantees
Read-Only / Closed-World go_workspace_brief, go_search, go_symbol_context, go_audit_concurrency, go_audit_errors Never executes compilers or test binaries. Completely safe for automated execution.
Execution Tools go_test_structured, go_race_report, go_verify_change, go_flake_finder, go_benchmark_diff Invokes local go toolchain to compile packages and run tests. Subject to timeouts and cancellation.
Guarded Mutation go_refactor Deterministic, content-addressed AST refactorings. Only modifies existing contained non-generated files after rechecking all file preimages against recovery journals.

Guarded Refactoring Invariants

  1. Content-Addressed Plan: Calling refactor preview produces an immutable plan ID bound to the exact Snapshot Ref and file preimages.
  2. Preimage Recheck: Before applying any edit, agentic-go verifies that every target file still matches its preimage bit-for-bit.
  3. Recovery Journal: A durable recovery journal is written prior to disk writes. agentic-go doctor --recover can restore clean state if interrupted.
  4. Zero Git State Mutation: Refactoring never runs git commit, git add, or branch commands.
