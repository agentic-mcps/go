The Verification Engine

The verification engine is the core product boundary shared by the CLI (agentic-go verify), GitHub Action, and MCP server (go_verify_change).

CLI Usage

Run a comprehensive verification against git base origin/main:

Terminal
$ agentic-go verify --base origin/main --package ./... --format text

Command Options

Flag Default Description
--base <ref> HEAD~1 (or main) Git ref, branch, or tree hash representing the baseline comparison.
--package <pattern> ./... Package selector. Impact analysis computes the full transitive closure of affected packages automatically.
--format <text|json> text Human-readable terminal summary or machine-readable agentic.verify/v1 JSON.
--race true Run tests under the Go race detector to catch data races.
--fail-on <level> error Threshold that triggers a non-zero exit code: error, warning, or findings.

Exit Codes

Deterministic exit codes make agentic-go verify reliable in CI and local scripts:

  • 0 (Pass): All requested packages compiled, tests passed without regressions, and no policy-blocking findings were introduced.
  • 1 (Policy Findings): Tests passed or were evaluated, but policy checks detected blocking findings (e.g. concurrency issues, error-handling bugs, scope drift).
  • 2 (Incomplete / Error): Compilation failure, unhandled runtime exception, or execution timeout prevented complete evaluation.

Verification Pipeline

  1. Snapshot & Impact Analysis: Computes the diff against --base, identifies modified declarations and comments, and resolves all downstream packages depending on altered code.
  2. Whole-Package Testing: Executes full package test suites. agentic-go deliberately avoids selecting individual test methods (e.g. -run TestSpecific) because partial test runs miss cross-test contamination and package init side-effects.
  3. Changed-Statement Coverage: Tracks coverage specifically across statements touched in the diff, reporting the exact coverage percentage on changed lines.
  4. Static Concurrency & Error Auditing: Analyzes goroutine lifecycles, channel operations, mutex copy semantics, and error wrapping conventions with a 0% false positive target.
  5. Uncertainty Calibration: Identifies unexercised branches, skipped tests, and environment constraints, reporting them explicitly in the output.
