## Decisions made

- Theme v0.2 around change-aware verification, not surface-area growth.
- Add one flagship read-only tool, `go_change_impact`, making the v0.2 target
  exactly eight tools while retaining four resources and four prompts.
- Derive a verification plan from local Git changes, Go declarations, package
  relationships, static calls, and test entry points. Return the evidence,
  confidence, and uncertainty behind every proposed step.
- Add `test_regex` to `go_test_structured` and `go_race_report` so an external
  agent can execute the selected tests through existing tools.
- Add an explicit `go_test_structured` detail selector with
  `summary | nonpassing | all`; default to `nonpassing`, preserve `verbose` as
  output control, and make filtering explicit in the response.
- Enrich existing audit results and `agentic-go://analysis-rules` with bounded
  rule rationale, remediation, limitations, source, and validation provenance.
- Upgrade `verify-change` to call the impact tool, execute its plan, broaden on
  uncertainty, and use `go_race_report` for structured race conflicts.
- Add no analyzer rules and change no detection predicate.
- Require focused contract coverage, one MCP dogfood, and the existing release
  matrix. Do not turn v0.2 into an A/B-agent or benchmarking research program.
