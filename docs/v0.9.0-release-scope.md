# v0.9.0 contract freeze

## Purpose

v0.9 freezes the local v1 product contracts before repository transfer and the
v1 release candidate. It adds no new MCP capability and makes no model,
reliability, token-saving, or adoption claim.

This document is authoritative for v0.9 behavior. The v0.2 release scope
remains the compatibility baseline, `contracts.md` remains authoritative for
shared invariants, and `v1.0.0-roadmap.md` governs the later transfer and
publication sequence.

## Frozen domain contracts

The following contracts become the only newly emitted versions:

| Contract | Frozen version | Pre-freeze archive |
| --- | --- | --- |
| Context Pack | `agentic.context/v1` | `agentic.context/v1alpha1` |
| Change Contract | `agentic.change/v1` | `agentic.change/v1alpha1` |
| Verification report | `agentic.verify/v1` | `agentic.verify/v1beta1` and the v0.2 alpha archive |

The v1 schemas retain the current field shapes and semantics. Freezing changes
the schema identity, not the meaning of a passing report, structural policy,
snapshot reference, location, truncation marker, or uncertainty.

Collections required by a schema remain non-null and deterministically
ordered. Locations remain workspace-relative with one-based UTF-8 byte
columns. Every intelligence result remains tied to one exact Snapshot Ref.
Result precedence remains `incomplete`, then `findings`, then `pass`.

Pre-freeze schemas move to `docs/schema/archive/` and remain immutable
historical evidence. Adapters emit v1 only. No compatibility flag emits an old
schema.

## Upgrade and archive behavior

Private `agentic.change/v1alpha1` contracts are accepted on load when their
complete existing invariants validate. They are returned in memory as
`agentic.change/v1` without changing the cache file. The next explicit
contract mutation writes v1 atomically. Unsupported schema identities and
malformed legacy state fail as corrupt state.

Private finalized `agentic.verify/v1beta1` reports remain readable by exact
content identity. New reports are finalized and stored as
`agentic.verify/v1`. Reading an archived report never rewrites it or advances
the latest pointer. The v0.2 alpha report was never part of this private store
and is retained only as checked-in historical evidence.

Context Packs and artifact cursors are snapshot-bound responses, not durable
cross-version storage. Existing private alpha artifacts remain opaque bytes;
v0.9 does not reinterpret or rewrite them.

Release archives remain deterministic for identical inputs. v0.9 evidence
must prepare the four supported archives twice, compare SHA-256 digests, verify
`checksums.txt`, and inspect required binaries and licenses.

## Frozen MCP interface

The v1 stdio surface is exactly:

- 14 tools;
- seven fixed resources;
- one `agentic-go://artifact/{id}` resource template; and
- six prompts.

`internal/tools.RegisterAll` remains the registration authority. A checked-in
normalized golden freezes tool names, input and output schemas, execution
annotations, resource URIs and MIME types, resource-template identity, prompt
names, and prompt arguments. Descriptions and list ordering are not frozen;
they may improve without changing behavior. Golden normalization sorts every
set by stable identity.

The seven v0.1 tools, additive `go_verify_change`, and later intelligence,
continuity, and refactor tools retain their current inputs and behavior.
Predictable check and policy failures remain structured results. Invalid
input, stale snapshots, containment failure, corrupt state, cancellation, and
deadlines remain protocol errors.

CLI compatibility retains these entry points and exit semantics:

```text
agentic-go
agentic-go --version
agentic-go verify
agentic-go doctor
agentic-go mcp-config
agentic-go contract export
agentic-go-vet
```

No arguments continue to start the stdio MCP server. No HTTP transport,
automatic client configuration edit, automatic toolchain installation, or
Windows support claim is added.

## Compatibility evidence

v0.9 adds focused evidence for behavior not already proven by existing suites:

- strict v1 schema identities and representative goldens;
- alpha Change Contract load, non-mutating read, and atomic promotion on the
  next explicit save;
- beta verification archive identity and read compatibility;
- the complete normalized MCP interface golden;
- exact companion acceptance and mismatch rejection;
- stale snapshot rejection and cancellation propagation;
- interrupted refactor recovery, repeated recovery, and divergence refusal;
- CLI entry points and verification exit codes; and
- deterministic release archives, installer checksums, and upgrade-oriented
  extraction.

Existing tests remain the authority where they already exercise these
properties. v0.9 adds no duplicate test merely to increase coverage counts.

## Deferred proposal classification

The release-candidate evidence classifies earlier proposals as follows:

- shipped locally: the v0.3 through v0.8 milestones recorded in the v1
  roadmap;
- retained research: the bounded paid pilot, additional navigation ideas,
  calibrated future analyzer domains, tier-2 tools, and creative workflows;
- rejected for v1: selective individual-test execution, SSA/VTA reachability,
  public test maps, SARIF, HTTP/SSE, hosted analysis, autonomous fixes, a
  language-plugin runtime, automatic dependency changes, and unverified
  Windows claims; and
- scheduled for the v1 release candidate: transfer to
  `github.com/agentic-mcps/go` and the explicit Go module identity migration.

Retained research is not a public promise. A future analyzer still requires a
positive fixture, meaningful near miss, limitation, production-path coverage,
and focused external calibration before it can emit findings.

## Completion gate

v0.9 is complete when:

- the three v1 schemas and representative goldens are checked in;
- archived schemas remain byte-stable and migration behavior is documented;
- the normalized MCP golden covers exactly 14 tools, seven resources, one
  template, and six prompts;
- upgrade, archive, stale-state, cancellation, and interruption evidence is
  clean;
- the supported Go 1.25, 1.26, and 1.27 matrix, race, vet, build, Staticcheck,
  golangci-lint, pinned-gopls contracts, four release targets, installer and
  Action adapters, signature inspection, and `git diff --check` pass; and
- the worktree is clean with a release-candidate evidence report.

No tag, push, transfer, release, paid pilot, or history rewrite is part of this
milestone.
