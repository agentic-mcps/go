# Road to v1.0.0

## Product direction

Agentic-go v1 is source-grounded Go change intelligence for coding agents:

> Keep an agent oriented before an edit, detect drift during the work, and
> verify the final change with executed evidence.

The product combines the current verification engine with gopls-grade semantic
understanding, compact Context Packs, persistent Change Contracts, stable
references, guarded deterministic refactoring, and explicit provenance and
uncertainty. It remains deterministic local tooling. It does not embed an LLM,
author arbitrary feature code, interpret goals semantically, or claim that a
passing report proves correctness.

## Authority and compatibility

The verification baseline is governed by
[`v0.2.0-release-scope.md`](v0.2.0-release-scope.md). This roadmap governs the
additive v0.3+ development stages only where a stage records implemented local
status. Shared protocol invariants remain in [`contracts.md`](contracts.md).
Existing v0.1 and v0.2 behavior remains compatible until a separate release
scope says otherwise.

The intended workflow is:

```text
Workspace Brief -> Begin Change -> Search / Symbol Context
  -> agent edits -> Checkpoint Change -> optional Refactor -> Verify Change
```

## Staged roadmap

### v0.3: foundation

Establish the supported distribution and semantic seam: a pinned gopls
companion, long-lived workspace sessions, capability reporting, cancellation,
restart and containment behavior, doctor diagnostics, checksums, and generated
MCP configuration. This foundation is implemented on `feat/v0.3.0`; it remains
unpublished until the earlier release gates and explicit publication approval
are complete.

### v0.4: semantic understanding

Add workspace briefs, bounded search, symbol context, stable Snapshot Refs and
Symbol Refs, compact Context Packs, pagination, provenance, and uncertainty.
Compare normalized semantic results with pinned gopls behavior across realistic
workspaces.

Implementation status: the core, `agentic.context/v1alpha1` schema, three MCP
tools, effective-capabilities resource, artifact cursor template, UTF-16/UTF-8
normalization, and pinned-gopls contract test are implemented locally on
`feat/v0.4.0`. Local dogfood covers agentic-go, Cobra, Gin, and grpc-go with
bounded responses and stable snapshot lineage. See
[`validation/v0.4.0/semantic-dogfood.md`](../validation/v0.4.0/semantic-dogfood.md).
The complete local milestone release matrix passes. Publication remains behind
the earlier release gates and explicit maintainer approval.

### v0.5: change continuity

Add Change Contracts and Checkpoints. Detect stale workspace state, scope drift,
public API and dependency changes, generated-file changes, test deletion, and
cross-module impact. Support deterministic handoff and resume across processes.

Implementation status: this milestone is implemented locally. The MCP surface
is 13 tools, six fixed resources, one resource template, and six prompts. The
Change Contract is private to the same machine and user cache, and every
checkpoint records exact snapshot lineage. Stale snapshots are rejected.
Structural policies cover scope, exported API shape, dependencies, generated
files, and test deletion. Goal and decision prose is retained for context, but
is never semantically enforced. The explicit CLI command
`agentic-go contract export --output <workspace-relative-path>` creates a
0600, contained, non-overwriting workspace copy. Normal operation does not
write into the worktree.

Exported API policy compares declaration shape. If source cannot be classified,
the result reports uncertainty rather than claiming that the API is unchanged.
This status makes no model, accuracy, or adoption claim.

### v0.6: guarded refactoring

Implemented locally. One `go_refactor` operation provides explicit preview and
apply for rename, formatting, import organization, and supported fix-all
actions. Preview produces a content-addressed private plan with the exact
Snapshot Ref, file preimages, bounded diff, and affected files. Apply accepts
only that plan ID and snapshot, rechecks every preimage, and writes a durable
recovery journal before changing source.

Only existing contained non-generated files may be changed. File creation,
deletion, resource operations, overlapping edits, stale snapshots, and
preimage drift fail closed. Apply never stages, commits, or changes Git
history. `agentic-go doctor --recover` restores an interrupted apply only when
every target still matches its recorded preimage or postimage.

### v0.7: unified verification

Implemented locally. `agentic.verify/v1beta1` adds a content-addressed report
ID, compiler and semantic diagnostic evidence, exact snapshot lineage,
provider capabilities, bounded context and refactor provenance, and optional
Change Contract compliance. CLI and production MCP verification use the same
intelligence service and report semantics. The current MCP inventory is 14
tools, seven fixed resources, one resource template, and six prompts.

Current-only diagnostics remain evidence with explicit baseline uncertainty;
they are not labeled as introduced defects. Contract policies block only for
machine-checkable `forbid` violations. Calibrated concurrency and error
analysis remain the only custom finding domains. New finding domains still
require the fixture, limitation, production-path, and external-calibration
evidence gate. The complete local matrix and self-dogfood are recorded in
[`validation/v0.7.0/unified-verification-dogfood.md`](../validation/v0.7.0/unified-verification-dogfood.md).

### v0.8: evaluation

Create a reproducible task corpus with pinned inputs, deterministic scorers,
recorded transcripts, cached baselines, and measurements for correctness,
scope safety, context bytes, duration, and tool calls. Run a bounded paid pilot
against native client tools, upstream gopls MCP, and agentic-go before making
any token or reliability claim.

### v0.9: contract freeze

Freeze the v1 MCP surface and context, change, and verification schemas. Run
migration, interruption, upgrade, archive, compatibility, and release-matrix
tests. Publish the release-candidate evidence report and classify every deferred
proposal as shipped, retained research, or rejected.

### v1.0.0: transfer and release

After the release candidate is independently verified, explicitly transfer the
repository to `github.com/agentic-mcps/go`, change the Go module identity,
update installation and schema references, publish an RC, repeat the complete
matrix against the organization repository, and tag v1.0.0 only after separate
approval. The module-path migration must be documented as a new package
identity, not presented as a seamless rename.

## Non-goals and release gates

Go is the only v1 implementation. MCP remains stdio-only. No hosted analysis,
agent orchestration, automatic commits, arbitrary code generation, dependency
upgrade policy, or universal model-accuracy claim ships without separate
evidence and approval. Refactoring must remain deterministic and reviewable.

Every v1 intelligence result must identify one observed snapshot, preserve
workspace containment, expose bounded totals and truncation, propagate
cancellation, and state meaningful uncertainty. No stale reference may be
silently re-resolved. No source, goal, decision, or absolute path belongs in
telemetry.

Refactor plans are immutable and content-addressed. Apply requires the exact
preview snapshot and every exact file preimage. Mutation is limited to
existing contained non-generated files, and interrupted recovery refuses any
target that has diverged from both recorded states.

Release evidence must cover supported Go versions and Darwin/Linux targets,
gopls protocol fidelity, stale-state and interruption recovery, MCP and CLI
compatibility, installer checksums, schema goldens, and a clean reviewable
worktree. Publication, repository transfer, tags, and pushes require explicit
maintainer approval.
